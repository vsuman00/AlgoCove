# Service degradation and application rollback

Owner: platform operator. Severity: page for multi-window request burn or database unavailability.

Containment: stop optional provider/indexing admission first. Preserve core authored learning when its database and execution dependencies are healthy. Return explicit unavailable responses when they are not. Infrastructure failures must never become negative mastery evidence.

Evidence: record UTC incident times, build ID, migration watermark, trace/request correlation, aggregate failure/latency counts and heartbeat age. Do not copy learner code, queries, prompts, response bodies, cookies or connection strings into incident notes.

Recovery: investigate configuration, connection saturation and database readiness. For application regressions, stop writers and start the prior retained immutable application build against the additive schema. Verify `/api/readiness`, the learning catalog and an owned synthetic saved-work journey. Never reset the shared dirty checkout or remove newer immutable attempts/content. Escalate incompatible schema changes to a forward fix or isolated database restore.

Communication: the operator reports impact, affected capabilities, containment and next update time to the incident owner. The privacy administrator reviews possible disclosure; the curriculum owner reviews credit/evidence impact. This runbook authorizes no automatic messages or hosted deployment.

Local evidence: [restore drill](../../docs/evidence/restore-drills/phase11-local-drill-2026-10-07.json). Hosted PITR and production load qualification belong to Task 57.
