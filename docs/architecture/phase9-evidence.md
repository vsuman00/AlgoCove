## Task 41: Durable jobs and operations

The immutable allowlisted registry and rotating relay reuse `platform.outbox_event` as the delivery authority. Only registered handlers' topics are claimed. Strict versioned descriptors contain bounded identifiers, checksums, policy/configuration versions or maintenance scopes; arbitrary private inline data is rejected. Leases are bounded to 1–60 seconds, automatic delivery attempts to 1–10, retry delays to 60 seconds and batches to 1–1000 events. Invalid descriptors dead-letter as `invalid_source`; exhausted retries use `retry_exhausted`. Output contains safe identities, counts and reason codes, never arbitrary exception messages or source text.

`0028_worker_effects.sql` adds immutable effect receipts and canonical derivation expectations. Database effects and their receipts commit atomically in a short transaction. Lost acknowledgement after commit permits redelivery without repeating the effect. Rollback before commit leaves no receipt. Topic and payload are checked against the stored event; claim ownership, unexpired lease and lifetime attempt fence effects and every delivery transition. Acknowledgement errors are not converted into effect failures.

Operator inspection, bounded maintenance admission and dead-letter replay check both application permissions and current database role grants. Replay is audited atomically, requires the inspected lifetime attempt count and refuses invalid descriptors. It keeps event identity, original payload and monotonically increasing lifetime attempts. `replay_attempt_base` resets only the retry budget, preserving stale-claim fencing.

Concrete reconciliation releases expired claims, marks withdrawn or mismatched content expectations obsolete, and recovers acknowledged-but-incomplete derivation dispatch when no effect receipt exists. Inspection exposes backlog age, dead letters, pending/quarantined expectations and available content lacking registration. Pending outputs remain pending; an acknowledgement or receipt never invents index readiness. Task 42 owns canonical derived artifacts, quarantine and index readiness.

Content derivation, embedding and evaluation handlers are typed adapters to module-owned consumers, with strict validation and current canonical admission for content jobs. Tests supply consumers to exercise that contract. At Task 41 closure, the standalone worker enabled reconciliation and optionally existing draft-expiry retention; Task 42 below adds explicit content composition. That initial composition did not register placeholder content/embedding/evaluation implementations. Absent consumers leave events pending. These owning modules must recheck canonical state at final commit, deduplicate their outputs, and impose deadlines on external operations outside database transactions.

Retention is explicitly disabled by default and deletes only drafts/revisions past their existing expiry timestamps. This is not account deletion or a new retention policy. The worker CLI separates dedicated consumer credentials from controlled operations credentials. Fresh-role provisioning grants only required maintenance access, including column-scoped publication metadata and expiry metadata; it denies learner/source text, authored statements, role-grant reads and table creation. See [worker operations](worker-operations.md).

Final repository validation also corrected trace-renderer hook ordering and guarded missing array values without removing the existing visual controls.

No interactive route runs these jobs. The worker executes finite batches and stops new claims on termination. Transaction timeout configuration now runs after `BEGIN`, making its local deadline effective; an actual PostgreSQL sleep fixture verifies timeout cancellation.

## Task 42: Pedagogical derivation and versioned indexes

**Complete locally on 2026-10-06 for the repository's governed original problem statements and authored hints.** The existing schema supports these pedagogical objects; it does not yet contain the other future curriculum object types. No arbitrary token splitting, scraped/licensed statement indexing, learner draft indexing, generated answer-key authoring or live embedding provider is introduced.

`packages/content` derives whole problem-statement and hint-tier units under `pedagogical.problem.v1`. Each immutable snapshot records canonical content/problem versions, the stored source checksum, a separately computed normalized payload/metadata checksum, scan version, concept/curriculum/language tags, visibility, source object, ordinal, hint ceiling and validity range. Target level remains explicitly `unspecified` because the existing source schema does not author it. Chunk identities derive from the parent index, ordinal and exact normalized text checksum. Line endings and Unicode are normalized; changed payload/metadata creates a different snapshot. Unknown policies, malformed metadata, invalid tier ladders and detected instruction markers fail closed. The versioned deterministic injection scan is defense in depth, not a semantic safety guarantee.

`0029_content_indexes.sql` adds immutable chunk text, PostgreSQL English `tsvector` documents with a GIN index, immutable versioned pgvector embeddings/configurations and safe quarantine failures. No approximate vector index or BM25 claim is made. Embedding identity includes provider, model, dimensions, normalization and policy version; dimensional, nonfinite, zero-vector and normalization errors are rejected. Prior vectors and configurations cannot be overwritten. Published hints are frozen with their governed parent, including late inserts, preventing silent teaching-payload changes after evaluation.

Publication now admits the deterministic derivation descriptor and expectation in the **existing publication transaction**. That transaction runs no derivation or provider call. The operator CLI also admits current published source for backfill; unchanged admission returns the original event identity. Module-owned workers derive outside their short commit transaction, then reload and lock current canonical content and compare the entire expected derivation before atomically writing artifacts, expectation state and immutable effect receipt. A narrowly scoped security-definer function locks the canonical row without granting content mutation. Lost acknowledgement permits redelivery with no duplicate chunks. Failed commits leave no partial index or receipt.

The worker's content composition is explicit via `WORKER_CONTENT_ENABLED=true`. Its freshly provisioned `content_indexing` role can read authored content and curriculum metadata and write candidates, but cannot read/delete learner drafts, mutate content, enable configurations or write evaluation references. The maintenance role gains only index identity/state metadata access for expiry reconciliation; it still cannot read chunk text or vectors. The embedding port is provider-neutral, cancellation-aware and bounded by an overall deadline before any database transaction. The executable fixture mode is explicitly local/test only and refuses `NODE_ENV=production`. Its SHA-256-derived vectors test pipeline durability; they do not claim semantic retrieval quality, provider approval or live evaluation.

Publication, completed derivation/embedding **expectations**, and evaluated retrieval **readiness** remain separate. Persisted outputs stay `candidate`; an expectation's `ready` means that particular artifact job completed. There is no promotion command in this task. Fixture configurations cannot be enabled by database constraint. A `ready` index additionally requires an evaluation reference; `search.eligible_chunk` rechecks current publication, payload, canonical checksum, validity and an enabled nonfixture configuration. Tasks 43/45 own learner query filters, corpus regression, approval integrity and promotion. The integration test's manually inserted approval/model is confined to its disposable database and proves the eligibility guard, not a production promotion.

Rights withdrawal atomically marks indexes and outstanding expectations obsolete in the retirement transaction; query-time guards reject expired rights even before maintenance runs. Bounded reconciliation also marks expired artifact and expectation states obsolete using only identity/state metadata. A provider result returning after withdrawal cannot commit vectors. Quarantine writes only a safe failure reason and affects the matching policy's candidate, preserving other versions. Text/vector artifacts remain immutable historical snapshots; legal takedown/account/backup purge is not implemented here and remains under the later privacy workflow.

## Task 43: Permission-first hybrid retrieval and immutable evidence

**Complete locally on 2026-10-06 for the declared original problem/hint corpus.** The implementation follows the retrieval contract in the data/AI architecture. Task 44, Phase 9 and Checkpoint F9 remain open. No learner query endpoint, live embedding/provider invocation, deployed index promotion or hosted deployment is introduced.

`packages/retrieval` now owns strict bounded request validation, versioned equal-weight reciprocal-rank fusion, deterministic ties, exact pedagogical-unit deduplication, whole-unit context budgeting, conservative version-disagreement flags and canonical evidence checksums. `PostgresRetrievalRepository` derives scope from an owned viable practice attempt, active database role grant, current published problem, compatible published curriculum and persisted hint exposure. Language, mode and effective ceiling come from server records. Solution-review tier six remains unavailable before submission, even with an exposure record. Cross-problem hints are excluded.

Both SQL rankers use a shared materialized permission-filtered relation before scoring. Filters include the immutable corpus index allowlist, evaluated readiness, original/current published available source, source checksum and validity/current rights, compatible curriculum/language/concepts, chunk scope/scan/level, tier and enabled matching model. Lexical retrieval uses PostgreSQL English `plainto_tsquery`/`ts_rank_cd` normalization 32; dense retrieval uses exact pgvector cosine distance. This is not labeled BM25. The repository performs no learner draft or source-code read and no provider call.

`0030_retrieval_evidence.sql` adds disabled-by-default immutable retrieval configurations and owner-bound immutable evidence receipts. The complete request/configuration/model/vector, original ranks/scores, candidate lineage/checksums, selected snippets/provenance, exclusions, confidence flags and timings are stored. Canonical sorted-key JSON survives JSONB reordering. Every candidate source is locked and rechecked before atomic persistence. An owner-scoped advisory lock serializes idempotent requests; identical retries return the original receipt, changed requests conflict. Reads/retries reauthorize the current scope and every ranked source, including unselected exclusions. Retiring an unselected source prevents serving the old package. Configured deadlines use remaining SQL timeout budgets; SQL cancellation yields dependency unavailability and failed persistence rolls back completely.

The [retrieval operations guide](retrieval-operations.md) records composition, authorization, failure/retry semantics, current limitations and the benchmark command. The [recorded pilot baseline](retrieval-baseline.json) pins the configuration, corpus snapshots/checksums, scope, environment, expected and returned IDs. The corpus contains 23 indexes and 15 forbidden control chunks; eight labeled queries run five times after three warmups. Recall@3 and MRR@3 are **1.0**; observed full retrieval/persistence latency is **7.31 ms p50 / 13.59 ms p95**, across 40 measurements. Vectors are an explicitly hand-authored local term basis, not a live semantic model. This small warm-loopback regression result does not establish wider pedagogical quality, production load latency, provider approval or Task 45 promotion.
